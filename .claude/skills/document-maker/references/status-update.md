# Status Update / Progress Report Template

## Structure

```markdown
# [Project Name] — Status Update
**Period:** [Week of / Sprint N / Month]
**Author:** [Name]
**Date:** [Date]
**Status:** 🟢 On Track | 🟡 At Risk | 🔴 Blocked

---

## Summary
[2–3 sentence plain-English summary of where things stand. Lead with the most important thing.]

## Accomplishments
- [Concrete thing completed — be specific, link PRs/tickets if relevant]
- [Another accomplishment]
- ...

## In Progress
- [What's actively being worked on]
- [Estimated completion if known]

## Up Next
- [What's planned for the next period]

## Blockers & Risks
| Item | Impact | Owner | Status |
|------|--------|-------|--------|
| [Blocker description] | [High/Med/Low] | [Person] | [Needs decision / In progress] |

## Decisions Needed (optional)
- [Any decision the audience needs to make or unblock]

## Metrics (optional)
| Metric | Last Period | This Period | Target |
|--------|-------------|-------------|--------|
| [e.g. Deploy frequency] | | | |
```

## Field Notes

- **Status emoji**: 🟢 = on track for commitments, 🟡 = at risk but recoverable, 🔴 = blocked/will miss
- **Accomplishments**: Always use past tense. Quantify where possible.
- **Blockers table**: Only include if there are actual blockers. Don't invent them.
- **Audience tuning**: For execs, make Summary longer and cut technical detail. For engineers, the opposite.
